## 9. 反模式清单（禁止）

| 反模式 | 后果 | 正确做法 |
|---|---|---|
| 无验收标准就开工 | 做偏、返工 | 先 S0，写清可测验收 |
| 小任务上全套流程（流程税） | 拖慢、形式主义 | 按 `02-效率与档位详解.md` §2.4 选档 |
| 无声明地偏离流程 | 规则形同虚设 | 声明理由 + 风险 + 回补 |
| 审计无限打磨 / 走过场 | 一边拖死、一边漏出 | 遵守 S4 终止条件与强度分级 |
| Lead 包办所有实现 | 成为瓶颈 | 拆分委派，Lead 守质量门与节奏 |
| 多 agent 抢同一文件 | 覆盖、冲突、重复劳动 | 写范围互斥，先申报后动 |
| 完成不附证据 | 假完成，后期爆雷 | 完成 = 实现 + 自检 + 证据 |
| 同一方案连试三次 | 时间黑洞 | 两次失败即换策略或升级 |
| 把「能跑」当「完成」 | 体验差、隐性债 | 真机按真实路径验证 |
| 需求变更直接插队实现 | 半成品叠加、反复返工 | 回 S0 评估影响并重排任务 |
| P0 问题无记录热修 | 复发、无法归因 | 止损 → 记录 → 修根因 → 补用例 |
| 过度设计/无限打磨 | 拖延、反馈滞后 | 先最小闭环，有反馈再优化 |
| 静默失败、吞异常 | 问题晚发现、难定位 | 失败可见、可诊断 |
| 擅自扩大范围 | 拖慢主线、引入风险 | 记录上报，走确认 |
| 绕过任务板沟通 | 事实源分裂 | 进度一律落回任务板 |
| 为改规则而改规则 | 规则膨胀失效 | 有反馈才改，无则写明理由 |
| 用对话记忆传结论 | 跨轮丢失、重复劳动 | 信息外置到文件（`06-协作细则.md` §6.6） |
| 每轮重读规则全文 | 上下文浪费 | 按 `AGENTS.core.md` §8 索引加载 |
| 频繁追问用户或闷头乱猜 | 拖慢或做偏 | 按 `07-用户交互与度量.md` §7 决策：带方案地问 |
| 反馈只记在脑子里、攒到轮末 | 漏掉、无法复用 | 即时登记，轮末归类（`01-总纲细则.md` §1.2） |
| 只挖负面反馈 | 有效做法与优化方向白白流失 | 三类都挖，正向要放大（`01-总纲细则.md` §1.2） |
| 审计抽样通过就收工 | 漏 bug → 整轮返工 | 逐条验收 + 清单维度 + 影响传播分析（`03-流水线.md` S4） |
| 只修表面逻辑就收工 | 同类/隐藏 bug 后续爆发 → 反复返工 | 修在根因，并追问同类路径与相关隐藏问题 |
| 只做明确要求的部分 | 半成品 → 用户发现不足再返工 | 主动补全/按最佳实践决策，拿不准就问 |
| 跟用户讲内部实现术语 | 用户看不懂、决策失真 | 用使用者能懂的宏观概念 |

## 10. 速查卡

**开工前**
1. 目的与验收清楚了吗（可测）？
2. 档位与时间盒定了吗？升档触发知道吗？
3. 写范围、依赖、主责、优先级定了吗？
4. 有没有更短路径？比较过两条吗？
5. 本轮会动到数据/接口/共享文件吗（→ 升档）？

**过程中**
1. 出现负面 / 正向 / 优化方向，记下来了吗（`01-总纲细则.md` §1.2 即时登记）？
2. 动手前先策划了吗？不可逆的先写决策记录了吗（`01-总纲细则.md` §1.4）？
3. 有阻塞预警信号了吗（`01-总纲细则.md` §1.7）？

**交付前**
1. 对照验收标准逐条自查了吗？
2. 边界/异常/失败路径处理了吗？
3. 有无屎山、死代码、调试残留？
4. 证据齐了吗？回退路径有吗？
5. 用户最初的目的达到了吗？

**每轮结束**
1. 哪里最慢？哪里最痛？
2. 哪条规则该改（或为何不改）？
3. 有效经验固化到哪了？
