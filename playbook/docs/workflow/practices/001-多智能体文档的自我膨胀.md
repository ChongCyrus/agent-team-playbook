## 协作文档越写越胖、常驻上下文吃满（本项目实例）

- **症状**：规则文件从 300 行涨到 640 行 / 1.6 万字符，每轮会话都被全文注入；改一次文件，
  整份文档就被重新塞进对话历史一次，长会话里重复累积。
- **根因**：规则「只增不减」+ 没有分流判据；且把"偶尔用不上"误判为"应该外移"，
  或反过来把所有细节都堆在同一个文件里。
- **解法**：
  1. 常驻核心只保留**每轮/每步都用**的（总纲、铁律、档位、硬条款、索引）；
  2. 按**使用占比**（不是"是否用得到"）决定去向：高频→核心，特定场景→分册，偶发→经验库；
  3. 核心设字符上限（默认 8k，可调），超限先下沉；
  4. 分册之间用「文件名 §节号」交叉引用，避免裸写 `§x`（拆文件后必然失效）；
  5. 核心与分册互标"摘要/完整版"，并约定冲突时以细则为真、立即回写摘要。
- **验证**：核心 16,756 → 4,677 字符（省约 72%）；机械校验（表格/围栏/引用可达）全过；
  与拆分前快照 diff 仅 5 行预期差异。
- **已固化到**：`AGENTS.md` §9（分流判据与验收线）+ §8（索引）+ 各分册头部引用约定
- **首次/复发**：2026-11-26 首次；根因类问题（"只增不减"）在多 agent 文档中高复发。
