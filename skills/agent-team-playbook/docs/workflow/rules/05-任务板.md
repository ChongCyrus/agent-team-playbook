## 5. 任务板规范

| 字段 | 要求 |
|---|---|
| ID / 标题 | 稳定、唯一、一眼看懂 |
| 目的 | 对应哪条验收标准 |
| 写范围 | 具体文件/目录，互斥；跨范围必须显式协调 |
| 依赖 | 明确 blocked by 谁；无依赖才可并行 |
| 主责 | 一任务一主责，避免共同负责 |
| 状态 | 待办 / 进行中（附断点备注）/ 阻塞 / 待审 / 完成 |
| 证据 | 测试结果、日志、截图、diff 要点 |

**纪律**
1. 先领取再动手，避免重复劳动。
2. 阻塞时更新状态并写清：阻塞点、已尝试方案、需要的决策/资源。
3. **完成 = 实现 + 自检 + 证据**，缺一不得置为完成。
4. 依赖变化立即同步，避免下游按旧前提施工。
5. 任务板是**唯一进度事实源**，口头进度都要落回板上。
6. 若任务板是共享单文件，由 Lead 独占写、队友提交变更请求——单文件多写是并发覆盖热点。

## 5.1 回流子条目（审计发现问题转任务时）

审计（`03-流水线.md` S4）产出的问题按等级分流后，需要回流本轮或转下一轮的，**必须在任务板建子条目**，不能只存在于对话或审计记录里。

| 子条目字段 | 说明 |
|---|---|
| 父任务 | 原任务 ID（便于追溯"这问题是从哪轮冒出来的"） |
| 来源 | 哪次审计（日期 / 审计记录路径） |
| 原问题等级 | 高 / 中 / 低（见 S4 分级表） |
| 转档依据 | 为什么走这个档位 |
| 回流深度 | 1 = 首轮回流；**超过 1 不再回流**，只登记 |

**纪律**

1. **深度上限 1 层**：回流子条目里再发现的问题只登记，不再建子条目——防止无限递归。
2. **父任务不算完成**：只要还有未处置的高等级回流条目，父任务不得置为「完成」。
3. **中/低等级出轮**：不在本轮修的中低等级问题，转成下一轮的首项任务，而不是挂在本轮。
