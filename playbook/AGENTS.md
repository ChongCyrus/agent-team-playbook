# AGENTS.md（常驻核心 · v1.22）

> **定位**：团队（Lead + 队友）共享的最高工作约定。本文件是**常驻最小集**；展开细则在 `docs/workflow/rules/`，按下文 §8 索引按需查阅。全文备份：`archive/AGENTS-v1.7-full.md`（拆分前最新全文）、`archive/AGENTS-v1.5-full.md`（更早快照）。
> **同源关系**：分册是本文件的展开解释，不是另一套规则。**原则与速查以本文件为准；细则细节以分册为准**——摘要与细则不一致时，以细则为真，并立即修正本文件。
> **总量受控**：本文件目标 **≤8k 字符（默认上限，可按实际需要调整）**；新增内容优先写进分册；分册单节 ≤12 条文字条款。

## 1. 总纲（全文最高原则）

> **过程中不断获取反馈，按实际反馈（负面反馈、正向反馈、优化方向）做相应的障碍消除/减弱、调整、优化改进；对象同时包括「项目本身」与「工作流本身」；动作上先策划（怎么消除/减弱，或优化改进方案），再执行。**

总纲服务于两件事：

1. **目的实现**：做出用户真正需要的东西，在真实使用场景下站得住，并且**合理、优越、健壮、完整**——不只是「能跑」：包含必要的完善与防御性处理（边界、异常、可维护性），避免交付半成品导致后续返工。用户常只给大体需求，**缺的部分要主动补全、按最佳实践决策，或拿不准就问用户**，不能默认不做。
2. **效率**：用尽可能少的时间与返工，稳定达成目的（效率 = 稳定性 × 速度；返工最贵，稳定性是最大的时间杠杆）。

**「目的实现」的展开**：**合理性**（做法对得住目的本身，也经得起用户真实体验的检验——不出现"技术上没错、用起来不合理"）｜**优越性**（比现有做法更好，而非凑合）｜**健壮性**（异常/边界/并发不崩不脏数据）｜**完整性**（主路径+分支+失败路径都覆盖）｜**必要的完善与防御性**（资源释放、幂等、可诊断、可维护）｜**用户视角**（站真实使用者角度判断「够不够用、好不好用」，而不是只对齐需求字面）｜**需求补全**（缺的主动补全、按最佳实践决策，拿不准就问）。

总纲不因任务规模而豁免，只调整轻重。**所有其它条款都是它的执行细则；冲突时以总纲为准。** 展开见 `docs/workflow/rules/01-总纲细则.md`。

## 2. 铁律（每轮必守）

> **总纲优先**：一切工作走「取反馈 → 分类 → 先策划 → 执行 → 固化」。

1. **先定完成标准**：验收标准必须可判真假。
2. **按风险选档**：不搞一刀切，裁剪必须声明并设定升档条件（§3）。
3. **先策划再执行**：动手前先问有没有更短路径；不可逆决策先记录。
4. **完成 = 实现 + 自检 + 证据**：无证据不算完成；**审计须全面、系统**（验收逐条 + 清单维度 + 边界/一致性/回归面），不做抽样式过一遍；**追到根因**——修完要问「还有没有同类/相关的隐藏 bug」，只消除表面问题不算完成。
5. **每轮复盘三问**：哪里最慢？哪里最痛？哪条规则该改？

## 3. 流程档位（速查）

| 档位 | 适用 | 必做 | 审计 | 验证 | 时间盒（参考） |
|---|---|---|---|---|---|
| **快速** | 单点改动、可逆、不动接口 | S0 一句话验收（修复型加复现 + 最小调查根因）+ S3 + 自测 | 自审：对照验收 + 扫边界 | 构建+自测 与 最小复现路径 | 15–30 分钟 |
| **标准** | 常规功能与修复，多文件但接口不变 | S0–S6 | 源码级 + 短测；有队友时交叉 | CI 绿 且 真实路径走通 | 半天 |
| **严格** | 数据、支付、安全、不可逆、对外契约、大重构 | 全流程 + 红队 + 双重审计 | 全清单 + 交叉 + 复审 | CI 全量绿 且 真实路径+异常+回退 | 1–2 天/子任务 |

时间盒以开场声明为准；严格档按**单个子任务**计，不是整个项目。**修复型任务在任何档位都要有"最小调查"**（快速档可缩到"复现即定位"），不允许跳过根因直接改。

**升档触发（任一即升档并重排任务）**：动数据/支付/权限/密钥；改对外接口或配置格式；触及共享文件；同一处两次修不好；新增依赖；真机失败且原因不明。

## 4. 反馈三类（速查）

- **负面** → 定根因 → 消除或减弱（不以绕过为终点）
- **正向** → 提炼并**放大**（写进模板/检查项/测试/脚本，让它默认发生）
- **优化方向** → 评估价值与成本 → 入待办或做小实验；不做就当没有

**即时登记**：`docs/workflow/feedback/<日期>.md`，一行 `类型 | 触发点 | 现象 | 初判动作`，按人分节；轮末汇总归类。

**五层扫描（保证不漏来源）**：目的层（真实体验/验收标准）｜策划层（设计/接口/依赖）｜实现层（代码/边界/并发/日志）｜过程层（等待/对齐/重复劳动）｜经验层（正向做法/踩过的坑）。详见 `docs/workflow/rules/01-总纲细则.md` §1.6。

**规则自身也要进化**：有反馈才改、不为改而改；改了要写清改什么/为什么/看哪个指标，并记入变更记录；先用一轮验证，有效固化、无效回退；重复或失效的条款直接删。详见 `01-总纲细则.md` §1.8。

**经验要落地（别只留在对话里）**：从反馈里得来的解法/套路，按下面三条路走，**不要停在"我知道了"**：

| 经验的使用频率 | 落到哪 |
|---|---|
| 每次都要用 | 提炼成条款进本文件（核心） |
| 特定阶段/场景才用 | 进 `docs/workflow/rules/` 对应分册，并在 §8 索引登记 |
| 偶发但复发时救命 | 进 `docs/workflow/practices/`（经验库，按问题类型组织，写法见其 README） |

每条经验必须写「**已固化到**：具体规则条款 / 检查项 / 测试 / 脚本」；填不出来的，说明还不是可执行经验。刻意不记 = 下次重踩。

## 5. 协作硬条款（每步生效）

- **单一事实源**：以工作区文件与实际运行结果为准；不臆测他人产出。
- **写范围互斥**：只动自己范围内的文件；必须越界先申请并同步影响。
- **先读后写**：冲突时重读再重排自己的改动，绝不强推覆盖。
- **证据说话**：测试、日志、复现步骤、diff；「我试过了」不算。
- **两次失败即报**：不闷头三连试，不隐瞒、不换法掩盖。
- **不空转**：等待期做无冲突准备（读上下文、写测试、备验证数据）。
- **长任务后台化**：预计超过约 1 分钟的操作（大下载、批量构建/测试、API 批量推送）挂后台跑，**不阻塞与用户的对话**；先回一句"已挂后台"，完成后再汇报结果。
- **不重复劳动**：动手前确认没人在做同一件事。
- **可逆优先**：删除/覆盖/发布/改数据先确认，能备份就备份。
- **消息自包含**：目的｜现状｜请求｜期望答复形式。

## 6. 开场与收尾

**开场（Lead，标准/严格档 3 行）**：①目标与可测验收 ②档位 + 时间盒 + 理由 ③分工与写范围。**快速档压成 1 行**。

**收尾（Lead）**：结果｜目的达成自评｜证据｜遗留与下一步（含未决风险）。

**一轮** = 一个用户目标从接受到验证通过的闭环；跨轮结论以文件为准，不靠对话记忆。

**对用户沟通**：默认用**使用者视角的概念**（做什么、带来什么、代价与风险），不用内部实现术语。**只有**满足其一才用内部术语：用户主动讨论/明确接受/已表现出能理解，或确实无法用宏观概念表达；用时应一句话解释。

## 9. 维护：写/改本文件前先分流（按使用占比判断）

**先估「使用占比」，再决定写在哪**。判据是出现频率，**不是**「有没有用不到的场合」：

| 使用占比 | 写到哪 |
|---|---|
| 绝大多数轮次/步骤都要遵守或查阅（**高频**） | **正文（本文件）** |
| 只有少数场景才用（**低频**：出事、换环境、跨轮交接、查历史） | 分册，正文留**一行触发点** |
| 高频但篇幅过长（超过一屏 / 一张大表 / 一段模板） | 正文留摘要与硬条款，细节进分册 |

**常见误判**：因为「它不适用于所有情况」就把高频内容外移——错。**偶尔用不上 ≠ 低频，只看占比。**

**动作**：下沉后同步 §8 索引（写清"何时必读"）；新增分册必须登记。**禁止**把整段细则、模板、长表、历史记录堆进正文（本文件）——正文只做三件事：**立原则、给速查、指路**。

**验收线**：本文件默认上限 **8k 字符**，超过即视为异常，先下沉或写明保留理由。**该上限是默认值、不是硬约束**——agent 可据实际情况调整：长期富余可下调，确有高频内容必须常驻可上调；**调整须写明理由**（推荐记入 `09` 的变更记录）。

- 分册改动后同步本索引，**并检查本文件的摘要条款是否仍一致**；每轮复盘检查索引是否仍有效。
- 版本变更记入 `09`；只留最近 3 版，旧版进 `archive/`。
