# 经验与做法库（Practices）

> **用途**：存放「从反馈中得来的经验、方法、套路」——负面反馈的根因与解法、正向做法的可复用模式、优化方向的评估结论。
> **不是**：任务记录、复盘原文（那些在 `review/`）、决策理由（在 `decisions.md`）。

## 为什么单独放这里

复盘日志按日期排列，跨轮检索困难；真正的价值在于**同类问题再次出现时能立刻找到上次怎么解的**。
本目录按「问题类型」组织，而不是按时间，便于复用。

## 收录标准

一条经验值得入库，需满足至少一条：

- 同类问题**出现过 ≥2 次**（说明会复发）；
- 解法**可跨项目复用**（不是一次性修补）；
- 踩坑代价高（定位耗时 > 30 分钟，或造成数据/发布事故）。

**不入库**：一次性的小修、纯上下文相关、没有可迁移结论的。

## 写法（每条尽量短）

```markdown
## <一句话标题：什么场景 / 什么坑>

- **症状**：会看到什么现象
- **根因**：为什么会这样（不是表面原因）
- **解法**：怎么做（可执行步骤）
- **验证**：怎么确认真的解决了
- **已固化到**：规则条款 / 检查项 / 测试 / 脚本（写具体位置）
- **首次/复发**：日期与次数
```

## 与规则的关系（重要）

经验入库后，**按使用频率决定去哪**：

| 使用频率 | 落点 |
|---|---|
| 每次任务都要用 | 提炼成条款进 `AGENTS.md`（核心） |
| 特定阶段/场景才用 | 进 `docs/workflow/rules/` 对应分册（并同步核心 §8 索引） |
| 偶发、但复发时救命 | 留在本目录，不上升到规则 |

**经验不是写进本目录就结束**——「已固化到」那栏必须填。填不出来的，说明它还不是可执行经验。
