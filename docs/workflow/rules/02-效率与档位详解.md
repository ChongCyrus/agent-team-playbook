## 2. 效率的两条腿

### 2.1 稳定性（质量底线）

- **健壮性**：异常输入、空值、超时、断网、并发、重复操作、中途取消都不崩、不脏数据。
- **无屎山**：分层清晰、职责单一、无重复实现、无死代码、命名达意、依赖可控；**遵循项目既有约定，不引入第二套风格**。
- **无 bug**：主路径与关键边界有测试或可复现验证，同类缺陷不重复出现。
- **可回归**：改动能被验证、问题能被复现、回退有路径。

### 2.2 时间账目

| 时间类型 | 说明 | 优化手段 |
|---|---|---|
| 动手 | 编码/写作 | 复用、模板化、减少无谓打磨 |
| 等待 | 等依赖、等审核、等回答 | 并行拆分、提前抛阻塞、预置桩/占位 |
| 返工 | 做错、做偏、做多 | 前置验收定义、先审策划、小步验证 |
| 对齐 | 沟通、解释、来回确认 | 任务书写清、消息自包含、批量沟通 |
| 切换 | 频繁换任务、换上下文 | 按依赖成组执行、减少打断 |

**优化优先级**：先砍返工与等待（收益最大），再压动手时间（收益最小、最易反噬稳定性）。

**成本同看**：上下文长度、模型调用次数、并发成员数也是资源——不是免费的，按需使用。

### 2.3 最优方案与决策记录

- **决策点前至少比较两条路径**（已有实现 / 已有工具 / 换拆法 / 最小闭环），选达成目的程度、成本、风险三者最优者；只有一条路时说明为何。
- 影响面较大或不可逆的决策，**把选择与理由写进决策记录**（`AGENTS.core.md` §7 产物落点），便于复盘与交接。
- 不为「完美方案」拖延：先做可验证的最小闭环，美化留到有反馈之后。
- 不为「快」牺牲不可逆的东西：数据、对外契约、安全、用户可见行为，先稳后快。
- **被否决的方案要留一行理由**（进决策记录），避免下轮重复提议同一个被否方案。

### 2.4 流程分档（避免一刀切与随意裁剪）

| 档位 | 适用 | 必做 | 可简化 | 审计强度 | 验证 | 时间盒（参考） |
|---|---|---|---|---|---|---|
| **快速** | 单点改动、文案/配置、可逆、不动接口 | S0 一句话验收 + S3 + 自测 | 任务书压成 3 行；S2 免；S6 压成 1 行 | 自审：对照验收 + 扫边界 | 最小复现路径 | 15–30 分钟 |
| **标准** | 常规功能与修复，多文件但接口不变 | S0–S6 | S2 改为自审；S6 可 3 行 | 源码级 + 短测；有队友时交叉 | 真实路径走通 | 半天 |
| **严格** | 数据、支付、安全、不可逆、对外契约、大重构 | 全流程 + 红队 + 双重审计 | 无 | 全清单 + 交叉 + 复审 | 真实路径 + 异常路径 + 回退演练 | 1–2 天 |

时间盒仅为参考值，**实际以开场协议声明为准**；不确定时按风险判档，不按"想快点"判档。严格档常跨多轮，时间盒按**单个子任务**计，不是整个项目。

**升档触发（出现任一，立即升档并重排任务）**：

- 涉及数据迁移/删除、支付、权限、密钥；
- 改动对外接口、契约、配置格式；
- 触及多人共享文件（配置、锁文件、统一入口）；
- 同一处两次修不好或原因不明；
- 新增第三方依赖；
- 真机验证失败且无法定位原因。

**裁剪纪律**：简化必须声明「本轮按 X 档执行，理由：…；已知风险：…；出现上述任一触发立即升档」。

### 2.5 优先级与取舍

多任务并存时的排序依据（自上而下）：

1. 用户明确指定的优先级；
2. 解除他人阻塞（被下游等待的任务）；
3. 关键路径上的任务；
4. 价值 ÷ 成本（含风险）更优的任务；
5. 顺手可清的快速清理（≤15 分钟；限于**写范围内、无行为变化**的纯本地改动，越界需 Lead 确认）。

**取舍规则**：每个成员同一时刻只推进一条主线；全局并行主线数由 Lead 控制（建议 ≤3）——**并行是为了压缩关键路径，不是为了显得快**。被打断时记录断点（做到哪、下一步、未验证的假设），避免回来重新推理。
