## 4. 任务书模板

```markdown
# 任务：<一句话标题>

## 目的
<为什么做，解决什么问题，对应哪个用户反馈>

## 验收标准（可测）
- [ ] ...
- [ ] ...

## 非目标
- 本次明确不做：...

## 根因（仅修复型必填）
- 现象与复现步骤：...
- 根因（有证据的结论，不是猜测）：...
- 为什么是这个根因（证据/实验）：...
- 同类问题是否也存在：...

## 约束与假设
- 技术/时间/兼容性/环境约束：...
- 关键假设（不成立需回头改哪一层）：...

## 方案要点
- 总体方案：...
- 模块与接口：...
- 实现步骤（L3）：1) ... 2) ... 3) ...

## 影响面与风险
- 触及文件/模块（= 写范围）：...
- 风险与缓解：...

## 验证方式
- 审计要点：...
- 短测/回归用例：...
- **CI/CD 门禁**：构建 / lint / 回归 / 产物校验（按档位）：...
- 真机路径：...

## 回退方案
- 失败时如何归零：...
```

**要求**：验收标准可判真假；步骤可独立分配；风险必须有缓解动作；写范围必须具体到文件/目录。

**修复型额外要求**：必须填「根因」段，且在方案里写明「修改点 → 为什么能消除根因（而非压症状）→ 同类问题是否一并处理」（见 `03-流水线.md` S1-B）。
